# todo-progress — TODO.md の進捗を数えて進捗サマリーと照らす

チェックリスト（`- [ ]` / `- [x]`）を節ごとに数え、進捗サマリーの表とずれていないかを確かめる。
数えるのも照らすのも `scripts/todo-progress.sh` が行う。手で数えたり、リポジトリごとに awk を書いたりしない。

```bash
S=~/.claude/skills/todo-progress/scripts/todo-progress.sh
bash "$S"                 # カレント（無ければ git のルート）の TODO.md を節ごとに数える
bash "$S" --check         # 進捗サマリーの表と照らす
bash "$S" docs/TODO.md --level 3 --total-label Total
```

```text
  66 /  103   64%  ## 1. 開発基盤・確認ツール
  18 /   26   69%  ## 2. 起動処理・メジャー版の共存（ADR-0001。PR #9）
 ...
 285 /  636   44%  合計

NG    line 37: 1. 開発基盤・確認ツール — the table says 65 / 102 (63%), the count is 66 / 103 (64%)
RESULT: 1 problem(s) — update the summary table
```

## PR を作る前の手順

1. その PR で終わる項目に `- [x]` を付ける（新しく足した項目も数に入る）
2. `bash "$S" --check` を実行する
3. `NG` の行を、出力の数に書き換える（割合は**切り捨て**。65 / 102 は 63%）。表に行の無い節は行を足す
4. 表の見出しの日付（「進捗サマリー（YYYY-MM-DD 時点）」など）を手で更新する。スクリプトは日付を照らさない
5. `RESULT: the summary table matches the counts` になるまで 2〜4 を繰り返す

レビューで「TODO.md の数が合っているか」を確かめるときも、`--check` の結果を書く。

## 数え方

| 対象 | 扱い |
|---|---|
| 節 | `--level`（既定 2）以下の見出し。それより深い見出しの項目は上の節に入る。同じ見出しは 1 つの節にまとめる |
| チェック項目 | `- [ ]` / `- [x]` / `[X]`、`*` `+` `1.` `1)` の印、字下げあり。`- [x]` の後に空白が無いもの・引用（`>`）の中は数えない |
| コードブロック | ```` ``` ```` / `~~~` の中は見出しもチェックも数えない |
| 最初の見出しより前の項目 | `(before the first heading)` の行に出す |
| チェックの無い節 | 出さない（合計には影響しない） |
| 割合 | 切り捨て（`int(100 * 完了 / 全体)`） |

## `--check` が照らす表

```markdown
| 節 | 完了 / 全体 | 進捗 | 状態 |
| --- | --- | --- | --- |
| 1. 開発基盤・確認ツール | 66 / 103 | 64% | … |
| 2. 起動処理・メジャー版の共存 | 18 / 26 | 69% | … |
| **合計** | **285 / 636** | **44%** | |
```

- 行のラベルは、「完了 / 全体」のセルより前の最初の空でないセル。太字・`[リンク](#…)` は外して読む
- ラベルは節の見出し（`#` を除いたもの）と同じか、見出しの先頭（続く文字が英数字でないとき）。
  「2. 起動処理・メジャー版の共存」は「## 2. 起動処理・メジャー版の共存（ADR-0001。PR #9）」に当たる。
  「Phase 1」は「## Phase 10 — …」には当たらない
- 「完了 / 全体」のセルは太字・3 桁区切りの `,` を許す。直後のセルが `NN%` なら割合も照らす
- 合計の行のラベルは `--total-label`（既定「合計」）

| 終了コード | 意味 |
|---|---|
| 0 | 表がすべて一致した（`--check` なしなら常に 0） |
| 1 | ずれた行、表に行の無い節、合計の行が無い、ラベルが複数の節に当たる |
| 2 | 照らせる表の行が 1 つも無い、引数の誤り、ファイルが無い |

どの節にも当たらない行は `NOTE` を出すだけで失敗にしない（節の名前を変えると、新しい名前の節が「行が無い」で失敗する）。
表の形が違うリポジトリ（「件数」だけの表など）では `--check` は 2 で終わる。数えるだけなら使える。表を上の形にすれば照らせる。

## 動作環境とテスト

- bash 3.2 以降と POSIX の awk。macOS の awk・mawk・busybox の awk で同じ結果になることを確認した（gawk は未確認）
- awk は `LC_ALL=C`（バイト単位）で動かす。パターンは ASCII だけなので結果は変わらない。
  macOS の awk は UTF-8 のロケールで、マルチバイト文字の 1 バイトにパターンを当てると「towc: multibyte conversion failure」で止まる
- busybox の awk は、`[^\]]` の括弧式が空白を含む文字列で外れ、未設定の値を変数に写すと文字列として比べる。
  スクリプトは POSIX どおりの `[^]]` を使い、比べる数は `+ 0` で数にしている
- シナリオテスト: `bash scripts/test-todo-progress.sh`（44 件。git が無い環境では既定のファイルの 3 件を飛ばす）。
  mawk や busybox で試すときは、その awk が `awk` になる環境（wp-env のコンテナなど）で実行する
