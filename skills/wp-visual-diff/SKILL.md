# wp-visual-diff — 見た目を変更前後で比べる

「見た目は変わっていない」と言うには、**変更前と変更後を同じ条件で測った数字**が要る。目で見比べるだけでは、数ピクセルのずれや、
片方のページがそもそも壊れていることを見落とす。このスキルは、変更前の版に一時的に差し替えて測り、変更後と比べる。

| ファイル | 役割 |
|---|---|
| `scripts/measure.js` | Playwright で各ページ × 各画面幅を開き、最後までスクロールして遅延読み込みの画像も読ませてから、HTTP の状態・WordPress の 404 テンプレートかどうか・全 `<img>` の位置とサイズ・読み込めなかった画像・ページの高さ・DOM の指紋（img の属性と CSS）を JSON に、全体のスクリーンショットを PNG に保存する |
| `scripts/swap-run.sh` | 指定した git の版（`--ref`）と違うファイルを、コマンドの実行中だけその版に戻し、終わったらバイト単位で元に戻す（失敗・Ctrl-C・kill でも）。未コミットの変更は既定で拒否し、`--allow-dirty` なら控えて戻す。シンボリックリンクは拒否する（通常のファイルになって戻るため）。差し替えに失敗したら、元に戻してコマンドを実行せずに exit 2。戻した後に照合し、合わなければ控えを残して exit 3 |
| `scripts/compare.py` | 2 回の計測を比べる。exit 0 差なし / 1 差あり / 2 比べられない（前提が崩れている。リダイレクトで前後の行き先が違う・スクリーンショットが無いも含む）/ 3 DOM が前後で同じ（差し替えが効いていない・ページキャッシュの疑い） |

必要なもの: Node と Playwright（chromium）、Python 3。Pillow があれば、スクリーンショットの差がどの行・どの画像かまで出る。

## 手順

### 1. 何をどの条件で測るかを決める

- **ページ**: 変更が効く画面に加え、効かないはずの画面も入れる（例: トップ・商品一覧・商品詳細 2 種類）。
  **公開中のページの URL を使う**。下書きの投稿や商品は 404 になる（実例: `?p=<下書きの ID>` で 404 ページを「商品詳細」として測り、比べていた）
- **画面幅**: 既定は 1280 と 390。`--dpr` は既定 1（スマホの実機は 2〜3。画像の選ばれ方が変わる。5 の読み方を参照）
- **ローカルのデータ**: 画像ファイル（uploads）が無いと、ロゴや商品画像が読めず、**壊れたページ同士を比べることになる**（`compare.py` が exit 2 で止める）。
  本番の複製を作るなら `wc-studio-prod-copy` スキルを使う
- **変更前の版**: 変更を含まない git の版（作業ブランチなら `main`、マージ後なら PR の前のコミット）

### 2. 変更後を測る（作業ツリーのまま）

```bash
S=<このスキルのディレクトリ>/scripts
OUT=<scratchpad>/visual-diff
node "$S/measure.js" --base http://localhost:8881 \
  --page top=/ --page shop=/shop/ --page product=/product/<slug>/ \
  --label after --out "$OUT"
```

各行の `WARN`（HTTP の状態・404 テンプレート・読み込めない画像）を見る。出ていたら、測る前提が崩れている（1 に戻る）。

### 3. 変更前を測る（swap-run.sh で一時的に戻す）

```bash
bash "$S/swap-run.sh" --repo <リポジトリ> --ref main --path wp-content/themes/<テーマ> -- \
  node "$S/measure.js" --base http://localhost:8881 --page top=/ --page shop=/shop/ --page product=/product/<slug>/ \
  --label before --out "$OUT"
```

- `--path` で差し替える範囲を絞る（サイトが読むディレクトリだけ）。差し替えたファイルの一覧と控えの場所が最初に出る
- 未コミットの変更があると拒否される。コミットするか、`--allow-dirty`（控えて戻す）を付ける。**`git show main:<file> > <file>` と `git checkout --` を手で行わない**（未コミットの変更が消える）
- 差し替える範囲にシンボリックリンクがあると拒否される。`--path` を絞って外す
- 終わったら `swap-run: restored N file(s)` が出ることと、`git status` が測る前と同じことを確かめる

### 4. 比べる

```bash
python3 "$S/compare.py" "$OUT/layout-before.json" "$OUT/layout-after.json"
```

### 5. 読み方

| exit | 意味 | 次にすること |
|---|---|---|
| 0 | 位置・サイズ・高さ・画素に差がない | スクリーンショットを目で見て、前後とも正しく表示されていることを確かめてから報告する |
| 1 | 差がある | 出たページ・画像・行の範囲をスクリーンショットで見る。意図した差か、既知の差か（下）、崩れかを判断する |
| 2 | 比べられない | 404・読み込めない画像・測ったページの食い違い・リダイレクトで前後の行き先が違う（`finalPath`）・スクリーンショットが無い。前提を直して測り直す（スクリーンショットを比べないなら `--no-pixels` でレイアウトだけ比べる） |
| 3 | DOM が前後でまったく同じ | 差し替えが効いていない（`--path` の範囲外）か、ページキャッシュが同じ HTML を返した疑い。DOM を変えない変更（PHP の内部処理など）なら `--allow-same-dom` |

**ぶれを見分ける**: 画像と重ならない数ピクセルの差（`may be text-rendering noise` の注記）は、日本語の文字の描画が回ごとにわずかに変わることで起きることがある。
同じ状態をもう 1 回測って（例: `--label before2` で 3 をもう一度）、`compare.py <before> <before2> --allow-same-dom` で同じ場所に差が出れば、変更とは関係のないぶれ
（実例: 変更前を 2 回測ると /shop/ と商品詳細の「〜」の周りに毎回差が出て、変更前の 2 回目と変更後を比べると消えた）。

既知の差（崩れではないもの）:

- **`sizes="auto"`**（遅延読み込みの画像に WordPress が付ける）: ブラウザーが表示幅から srcset の候補を選ぶので、DPR 1 では前より小さい画像を選ぶことがある。
  位置・サイズは同じで、画素だけ違う。DPR 3 では同じ画像になることが多い。表示幅より小さい画像を選んでいなければ問題ない
- **動的な内容**: 日付、ランダムな商品、カートの数、アニメーション

報告では、**「差がない」は「変更前と同じ」であって「正しい」ではない**ことを踏まえる。前後とも同じように壊れていれば差は 0 になる。
スクリーンショットを必ず目で見て、壊れていないことも書く。

## 落とし穴

- **`waitUntil: 'networkidle'` は WordPress では終わらないことがある**（アクセス解析・Jetpack などの通信が続く）。`measure.js` は `load` の後に `--settle`（既定 1.5 秒）待つ
- **画像ファイルが無いと、`sizes="auto"` の画像は高さ 1500px の空の枠になる**（WordPress の CSS `contain-intrinsic-size: 3000px 1500px`）。ページの高さが本番と大きく違ったら、まず画像を疑う
- **ページキャッシュ**: `measure.js` は URL に `vdiff=<label>-<時刻>` を付けて素通りする（`--no-cache-bust` で外せる）
- **スクリプトから Ctrl-C を送るテスト**: バックグラウンドで起動したプロセスは SIGINT が無視された状態で始まる（`set -m` でジョブ制御を有効にしてから起動する）。`swap-run.sh` 自体は、端末での Ctrl-C と `kill`（TERM）で元に戻す

## テスト

```bash
bash scripts/test-swap-run.sh "$PWD/scripts/swap-run.sh"
bash scripts/test-compare.sh "$PWD/scripts/compare.py"
node --check scripts/measure.js
```
