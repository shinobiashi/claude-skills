# Markdown マニュアルの docx 化

複数の `.md` を結合して 1 本の docx にする。ローカル画像は docx 内に埋め込まれるので、
できあがった docx を Google ドライブに置けば画像込みで Google ドキュメントになる。

## なぜ docx を経由するのか

Markdown をそのまま Drive にアップロードしても Google ドキュメントに変換はされるが、
**画像は壊れる**。Drive の Markdown 変換は本文テキストしか見ないため、`./images/foo.png`
のようなローカル参照を解決できない。pandoc で docx を作ると画像がファイル内に埋め込まれ、
Drive の docx 変換はそれをそのまま引き継ぐので、画像入りのマニュアルはこの経路が確実。

## 前提

- `pandoc`（`brew install pandoc` / `apt install pandoc`）
- Node.js（スクリプトは標準モジュールのみ使用）
- Mermaid 図がある場合のみ `@mermaid-js/mermaid-cli`

## 手順

### 1. 対象ファイルと順序を決める

順序はドキュメントの読みやすさを左右するので、勝手にグロブ展開で済ませない。
次の優先順で判断し、決めた順序をユーザーに提示してから進める。

1. `SUMMARY.md`（GitBook 形式）があれば、そのリンク順
2. `mkdocs.yml` / `docusaurus.config.js` があれば、その nav 定義順
3. `README.md` に目次リンクがあれば、その順
4. どれも無ければファイル名の昇順（`01-`, `02-` のような接頭辞があれば素直に従う）

`README.md` は概要として先頭に置くのが自然なことが多いが、各章の内容と重複している場合は
除外を提案する。

### 2. Mermaid 図を PNG にする

pandoc は Mermaid を解釈せず、コードブロックのまま出力してしまう。
対象 md に ```` ```mermaid ```` があれば、変換前に画像化して参照を差し替える。

```bash
mmdc -i diagram.mmd -o diagram.png -w 1200 -b white
```

SVG は docx 経由で欠けることがあるため PNG を使う。図が多い場合は、
元 md には Mermaid を残したまま、変換用のコピーを作って差し替える方が管理しやすい。

### 3. 変換する

```bash
node scripts/build-manual.mjs \
  --title "SAAI CRM 管理者マニュアル" \
  --chapters \
  --out ./dist/manual.docx \
  docs/setup/*.md docs/api/*.md
```

| オプション | 説明 |
| --- | --- |
| `-t, --title` | ドキュメントのタイトル（必須） |
| `-o, --out` | 出力先 docx（既定は `./<タイトル>.docx`） |
| `-c, --chapters` | 各ファイルを 1 章として扱う |
| `-r, --reference-doc` | 体裁を揃えるためのテンプレート docx |

スクリプトがやること:

- 画像の相対パスを各 md の位置を基準に絶対パス化する（ファイルが別ディレクトリにあっても衝突しない）
- HTML の `<img>` を Markdown 記法に変換する（docx 書き出しでは生 HTML が捨てられるため）
- リンク切れの画像は警告を出し、本文にはプレースホルダを置く（変換自体は止めない）
- コードフェンス内は一切書き換えない（`# コメント` を見出しと誤認しないため）

`--chapters` の挙動は、各ファイルの先頭に H1 があればそれを章見出しに転用し、無ければ
ファイル名を章見出しにして残りの見出しを 1 段下げる。**変換後に警告を必ずユーザーに伝える。**
リンク切れ画像は元 md 側の不備であることが多く、黙って進めると気づかれないまま配布される。

### 4. Google ドキュメントにする

ここは手作業でよい。API 認証を組むのは、更新が頻繁になってからで足りる。

1. 生成した docx を Google ドライブにドラッグ&ドロップする
2. その docx をダブルクリックで開く
3. 「ファイル → Google ドキュメントとして保存」

見出しは Google ドキュメントの見出しスタイルに対応するので、
**「挿入 → 目次」で目次が自動生成できる**ことを案内する。pandoc の `--toc` は
docx フィールドとして出力され Google ドキュメント側で空になることがあるため、使わない。

## 体裁を揃えたいとき

同じマニュアルを継続的に更新するなら、テンプレート docx を一度作っておく。

```bash
pandoc --print-default-data-file reference.docx > template.docx
```

これを Word や Google ドキュメントで開き、見出しフォント・余白・本文サイズを編集して保存し、
`--reference-doc template.docx` で毎回適用する。プロジェクト直下の `docs/template.docx`
のような固定位置に置いておくと、次回以降ユーザーに聞かずに済む。

## よくある詰まりどころ

**画像が巨大に出る** — スクリーンショットは原寸で入るため、ページ幅を超えることがある。
元 md 側に pandoc 拡張の `![キャプション](img.png){width=60%}` を書けば効く。
複数枚が同じ問題を抱えている場合は、元 md への一括追記を提案する。

**表が崩れる** — pandoc の gfm パーサはセル内の改行を扱えない。
`<br>` を含む表は事前に整形するか、リスト形式に直す。

**日本語フォントが変わる** — docx 側のフォント指定が Google ドキュメントで
置換されることがある。テンプレート docx で本文フォントを明示すると安定する。

**変換後に差分を確認したい** — スクリプトは結合後の Markdown のパスを出力する。
出力がおかしいときは docx ではなくまずこのファイルを見る。
